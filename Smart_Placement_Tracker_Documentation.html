System Design & Tech Stack Specification

Smart Placement Tracker (SPT)

Complete Technical Architecture, Features, and Database Documentation

1. Executive Summary & Overview

The Smart Placement Tracker (SPT) is a full-stack MERN application built to help university students organize, track, and streamline their placement job applications. Incorporating a dynamic drag-and-drop Kanban Board, real-time community chat rooms, a customized Resume ATS keyword scanner, and an interactive mock interview prep hub, the application serves as a comprehensive tool during placement seasons.

2. High-Level System Architecture

The application is designed around three main layers: a rich SPA client tier built with React and Vite, a stateless RESTful and WebSocket server tier powered by Express and Socket.IO, and a document database tier managed via MongoDB and Mongoose schemas.

5. Backend API Endpoints Catalog

The Express backend exposes secure endpoints grouped into five routes, all mapped from /api:

Authentication Endpoints (/api/auth)

  • POST /register: Signs up a user profile using unique emails and hashed passwords.
  • POST /login: Verifies input passwords and returns signed access JWT tokens.
  • GET /me: Securely retrieves authenticated profile info. (Auth Required)

Job Board Endpoints (/api/jobs)

  • GET /: Fetches all job application cards stored by the user. (Auth Required)
  • GET /interviews: Retrieves only jobs currently in the Interview status. (Auth Required)
  • POST /: Adds a new job application document. (Auth Required)
  • PUT /:id: Modifies job details, notes, meeting links, or feedback. (Auth Required)
  • DELETE /:id: Permanently deletes a job application card. (Auth Required)
  • PATCH /:id/status: Performs column updates on card drags. (Auth Required)

Resume Endpoints (/api/resume)

  • POST /upload: Receives and parses PDF/DOCX resume files, storing files in local uploads directories. (Auth Required)
  • GET /: Fetches the extracted text contents and metadata of the saved file. (Auth Required)
  • GET /download: Pipes files back to client for rendering. (Auth Query Token Required)
  • DELETE /: Wipes resume database entries and unlinks storage files. (Auth Required)

Real-time Chat Endpoints (/api/chat)

  • GET /rooms/list: Fetches room objects, unread/message counts, and last comments. (Auth Required)
  • GET /:room: Returns page-sorted message history for a specific room. (Auth Required)

Notifications Endpoints (/api/notifications)

  • GET /: Returns notification objects for the user. (Auth Required)
  • PUT /read-all: Flags all unread notification objects as read. (Auth Required)
  • PUT /:id/read: Flags a single notification as read. (Auth Required)
  • DELETE /:id: Removes a notification. (Auth Required)

6. External & Browser Integrations

The application makes extensive use of built-in HTML5 features and simulated API responses to enable key client-side flows:

  1. Speech Recognition: Captured by the browser's SpeechRecognition Web API to transcribe mock interview answers live.
  2. Speech Synthesis: Executed by window.speechSynthesis to read interviewer prompts aloud.
  3. Simulated Question API: Located in MockTests.jsx. It provides fallback mocks to search and fetch developer topics dynamically when the database does not contain matches.
